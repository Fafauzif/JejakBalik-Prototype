# JejakBalik 3.0

The earlier experience showed authored operations and separate scenario/history views. This release introduces a shared editable recovery network that calculates pickup and receiving insertions into existing journeys.

## Current capabilities

- Three fictional transport providers, six journeys and 18 sample devices across ten categories.
- Fixed road geography with deterministic matching, receiving/time/handling/capacity/budget checks and visible unmatched requests.
- Explicit revision-bound approval, chronological simulated custody, protected data reviews and preserved physical-custody holds.
- Background planning with stale-result rejection, editable provider capacity/compensation, collection windows and receiving constraints.
- Network, Requests, Decisions and Results share one scenario; older routes resolve into current workspaces.
- Richer fixed miniature, distinct fleets, original/planned/additional-traversal overlays, cargo inspection, receiving interiors and component views.
- Adaptive/light/high renderer modes, reduced motion, an immediately usable interactive map and renderer recovery.
- Local scenario persistence, validated import, provenance-bearing JSON/CSV and a controlled optional intake assistant.

## Installation compatibility

The archive is a complete source overlay. Extract it into the current repository root and replace matching files. Retired modules remain inactive and do not require a manual directory purge. New version 3 storage is separate from legacy records. Imported or restored proposals require fresh review before further service progression.

## Interpretation

All operating inputs and events are fictional. Calculated feasibility and test results are software evidence. No field collection, partner agreement, sanitization, payment, environmental impact or deployed integration is implied. Planning is pre-departure and heuristic; live-position routing is outside this implementation. A grouped comparator reports its own service feasibility and coverage.

Exact executed checks and limitations are recorded in `V3_VERIFICATION.json`. Prior release records are historical.
