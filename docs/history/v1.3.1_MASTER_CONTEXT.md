## Shared event and decision model

The canonical Tutorial service date is 19 October 2026, timezone Asia/Jakarta. Its operational results derive from immutable seed records, ordered authored events, scoped decisions, and the current cursor. Continuous observation and historical-period results have the separate, explicit sources described above. No screen owns independent collection or completion counters. A snapshot exposes asset states, exact custody-event IDs, requests, current eligible routes, decisions, window context, and metrics. Prefix derivation makes seek/replay deterministic and prevents duplicate custody entries.

Asset lifecycle: draft/requested → validated → scheduled → assigned → collected → received → triaged → routed → completed. Every event checks submitted request, selected scenario/window membership, reached timestamp, previous lifecycle state, and relevant gate. Routing and completion also require compatible receiving capacity, destination, no active safety hold, and data clearance for data-bearing devices. Visible destination is planned until a completion event records an actual eligible outcome.

Session scope is `(scenarioId, batchId, windowId)`. Decisions include scope, action, ID, and checkpoint story second. The three explicit checkpoints are:

| Checkpoint          | Story second | Authorized actions                             |
| ------------------- | -----------: | ---------------------------------------------- |
| Hero submission     |           32 | `submit_hero`                                  |
| Specialist handling |           74 | `approve_specialist`, `retain_specialist_hold` |
| Data release        |          130 | `approve_data_release`, `retain_data_hold`     |

A valid review token matches gate, scope, exact cursor, revision, and paused state. Tokens are single use. Seeking invalidates them. Revisiting a gate explicitly rewinds to its checkpoint, clears that gate and later decisions, and increments the revision. Switching/restoring/importing scopes invalidates live review tokens. Approvals never occur simply from play, seek, scenario change, reset, export, or import. Retaining a hold is a valid inspectable outcome rather than a forced happy path.

The guided story has an authored 180-second timeline. It opens the city, household form, team artifacts, route, hub, device, destinations, and household outcome/impact. It pauses for submission, specialist/data decisions, artifact inspection, component inspection, and outcome review. User dwell does not consume story time. Early guided hero confirmation waits for the actual 32-second checkpoint; free exploration can explicitly review that checkpoint. Playback supports 0.5×, 1×, 2×, 5×, 10× and 30×, plus pause, seek, replay, resume and Next. Next advances to a meaningful stage while honoring the exact review checkpoints and guided inspection stops; it never submits a request or accepts a decision. Changing speed changes elapsed wall time rather than authored story length. Document visibility pauses Tutorial playback.

Each record retains category, realistic per-unit mass, condition, household/request alias, service date, current status, clearance, planned or final pathway, and custody events. The ledger is generated deterministically once, then recursively frozen. Search, category/status/tab filters, sort and pagination are bounded and URL-backed. Impact selects the same monthly or year-to-date ledger and derives completed recovery mass, returned-to-use devices, outcome mix, monthly trend, served households and work in progress. Completed results exclude unfinished devices. Reuse, repair and refurbishment count as returned to use; component/material recovery and specialist treatment are separate outcomes.

The transport comparison includes the identical already-collected devices and household/handling-class groups on both sides. Dedicated trips travel hub–one household–hub; grouped routes combine compatible households within vehicle mass and item limits. Both alternatives use the same kilometre rates and dispatch fees, with Manhattan distances from the same coordinates. Downstream hub-to-destination legs are excluded from both alternatives. Individual routes and coverage remain inspectable in the period JSON.

Service-contract funding and community-access support are attached to each cohort. Gross recovered value remains downstream; only the 20% platform share enters revenue. Contribution equals contract funding + access support + platform recovered-value share − grouped collection − completed-device processing − recorded data-clearance cost. The model excludes overhead, capital, tax and working capital; contribution is not net profit and may be negative for a selected period. Inputs, formulas and boundaries are documented in `docs/OPERATING_HISTORY.md` and available in JSON.

The period report is a bounded, localized HTML/print report containing aggregate outcomes, collection comparison, funding/cost lines and the monthly breakdown. It does not print thousands of device rows. Device CSV, monthly-summary CSV and period JSON contain the corresponding detailed records. The original Tutorial batch report and session import/export remain independent and continue to reflect the selected Tutorial position.

## Additional requests and persistence

Additional requests do not append physical load or funding to the canonical completed day. The application allows up to six extra requests with 1–3 devices each. Category and condition choose an authored template/pathway. Items allocate by ordered request/item priority, handling class, vehicle mass/slot limits, and receiving capacity. Overflow reserves the next available date. New exploration dates begin no earlier than 21 October after prior canonical reservations. A started batch cannot accept later edits; late requests form a new batch, retaining prior reservations. A household with multiple windows aggregates truthful partial/final outcomes without multiplying counts from other requests.

The JSON schema stores scenario, active batch/window, saved scoped sessions, real decisions, exploration records, chronological reservations, service timezone, locale, quality, speed, motion preference, and valid selection. Import validates references, source templates, capacities, chronological reservations, and decision structure. It rejects malformed/oversized/unsupported input without replacing the current state. Review tokens never restore as live authorizations. Corrupt storage creates a recoverable fresh session. Reset active scenario and reset exploration have separate explicit confirmations and clear scope.

Tutorial CSV downloads contain the actual selected assets or custody rows, UTF-8 BOM, correct escaping, and spreadsheet-formula protection. Its report is localized readable HTML, with deliberate print styling, exact state totals, repeated table headings, and the actual identity. Its PDF is produced by browser printing when requested. No data-erasure or processor certificate is fabricated.
